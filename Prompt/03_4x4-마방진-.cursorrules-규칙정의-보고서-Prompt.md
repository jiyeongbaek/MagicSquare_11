각 섹션 작성 규칙:

code_style:
  - python_version: "3.10+"
  - style_guide: PEP8 엄격 준수
  - type_hints: 모든 함수 파라미터와 반환값에 필수
  - docstring: Google 스타일, 모든 public 메서드에 필수
  - max_line_length: 88 (Black 기준)

architecture:
  ECB 패턴 3 레이어를 각각 정의해줘:
  - boundary: 외부 입출력 담당 (UI, API, CLI)
  - control: 비즈니스 로직 담당
  - entity: 도메인 데이터 및 규칙 담당
  레이어 간 의존성 방향도 명시해줘.

tdd_rules:
  지금은 문자열 1줄인데, 하위 항목으로 세분화해줘.
  각 phase마다:
    - description: 단계 설명
    - rules: 지켜야 할 규칙 목록
    - must_not: 이 단계에서 하면 안 되는 것

testing:
  - framework: pytest
  - pattern: AAA (Arrange-Act-Assert)
  - coverage_minimum: 80%
  - fixture_scope: 규칙 정의
  - naming_convention: test_ 접두사 필수

forbidden:
  항목마다 아래 구조로 작성:
    pattern: 금지 패턴
    reason: 금지 이유
    alternative: 대신 써야 할 것
  최소 포함 항목: print(), 하드코딩 상수, except 단독 사용

file_structure:
  ECB 기준 폴더 구조를 트리 형태 주석으로 작성해줘.
  boundary/, control/, entity/, tests/ 포함.

ai_behavior:
  Cursor AI가 코드 생성 전·중·후에 반드시 따라야 할 규칙.
  최소 포함:
    - 코드 작성 전 관련 테스트 파일 확인
    - ECB 레이어 경계 위반 금지
    - 타입힌트 없는 함수 생성 금지
    - tdd_rules 위반 시 경고 출력

요청하신 기준을 반영해 `.cursorrules`의 빈 섹션을 전부 채우고, 파일도 실제로 업데이트한 뒤 전체 내용을 그대로 드리겠습니다. 우선 현재 파일에 맞춰 한 번에 패치 적용하겠습니다.

파일 반영은 완료됐고, 문법 이상 여부만 한 번 더 점검한 뒤 전체 `.cursorrules` 내용을 그대로 출력하겠습니다.

```yaml
################################################################################
project:
  name: MagicSquare_XX
  domain: 4x4 magic square solver and validator
  primary_language: python
  goals:
    - Maintain strict ECB layered architecture.
    - Enforce TDD workflow for all feature and bugfix work.
    - Keep code testable, typed, and easy to review.

################################################################################
code_style:
  python_version: "3.10+"
  style_guide: PEP8 strict compliance
  type_hints: Required for all function parameters and return values
  docstring: Google style required for all public methods
  max_line_length: 88

################################################################################
architecture:
  pattern: ECB
  layers:
    boundary:
      role: Handles external input and output such as UI, API, and CLI.
      examples:
        - ui
        - api
        - cli
    control:
      role: Contains business logic and application flow orchestration.
      examples:
        - use_cases
        - services
        - coordinators
    entity:
      role: Defines domain data models and core domain rules.
      examples:
        - models
        - value_objects
        - domain_rules
  dependency_direction:
    - boundary -> control
    - control -> entity
    - entity -> (no outward dependency)
  boundary_rules:
    - boundary must not import entity directly.
    - boundary must delegate business decisions to control.
    - control may use entity but must not depend on boundary.

################################################################################
tdd_rules:
  red_phase:
    description: Write a failing test first and verify the failure reason.
    rules:
      - Add or update tests before writing production code.
      - Confirm the new test fails for the expected reason.
      - Keep the failing scope focused on one behavior.
    must_not:
      - Do not write production implementation before a failing test exists.
      - Do not move to green phase without observing test failure.
  green_phase:
    description: Make tests pass with the minimal implementation only.
    rules:
      - Implement the smallest code change to pass failing tests.
      - Run related tests after each code change.
      - Stop once tests pass; postpone cleanup to refactor phase.
    must_not:
      - Do not refactor structure in this phase.
      - Do not add untested extra features.
  refactor_phase:
    description: Improve structure without changing externally observable behavior.
    rules:
      - Refactor only after tests are green.
      - Keep all tests passing before and after each refactor step.
      - Maintain coverage baseline while reducing duplication and complexity.
    must_not:
      - Do not change feature behavior or public contracts.
      - Do not reduce existing test coverage.

################################################################################
testing:
  framework: pytest
  pattern: AAA (Arrange-Act-Assert)
  coverage_minimum: "80%"
  fixture_scope:
    default: function
    allowed:
      - function
      - class
      - module
      - session
    rules:
      - Use the narrowest possible fixture scope by default.
      - Use broader scopes only when setup cost is high and state isolation is preserved.
  naming_convention: test_ prefix is required for all test files and test functions

################################################################################
forbidden:
  - pattern: print()
    reason: Produces uncontrolled console output and bypasses project logging policy.
    alternative: Use structured logging via the configured logger.
  - pattern: hardcoded constants in business logic
    reason: Makes rules brittle and difficult to maintain or test.
    alternative: Define named constants or configuration values in a dedicated module.
  - pattern: bare except
    reason: Hides real errors and can swallow critical exceptions unexpectedly.
    alternative: Catch specific exception types and handle them explicitly.

################################################################################
file_structure:
  # MagicSquare_XX/
  #   boundary/
  #     ui/
  #     api/
  #     cli/
  #   control/
  #     use_cases/
  #     services/
  #   entity/
  #     models/
  #     rules/
  #   tests/
  #     boundary/
  #     control/
  #     entity/
  #     integration/

################################################################################
ai_behavior:
  before_codegen:
    - Check related test files before writing or modifying production code.
    - Confirm target module belongs to the correct ECB layer.
  during_codegen:
    - Do not violate ECB layer boundaries.
    - Do not generate functions without type hints for parameters and return values.
    - Follow active tdd_rules phase constraints at all times.
  after_codegen:
    - Run or update relevant tests and report results.
    - If any tdd_rules violation is detected, output a clear warning and halt further code generation until resolved.
```
