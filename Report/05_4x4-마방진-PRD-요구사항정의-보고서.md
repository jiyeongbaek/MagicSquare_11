# 05_4x4-마방진-PRD-요구사항정의-보고서

## 1. 작업 개요

- 대상 문서: `docs/PRD_4x4_MagicSquare_TDD.md`
- 목적: 기존 Dual-Track(UI/Logic) TDD PRD를 유지하면서 MLOps 관점을 포함한 확장형 요구사항으로 보완
- 결과: 문서를 `Dual-Track + MLOps Track` 기반의 Tri-Track PRD로 업데이트

## 2. 이번 작업에서 반영한 핵심 변경

### 2.1 문서 방향성 보강

- 문서 목적에서 "순수 로직 중심" 표현을 "경계/도메인/운영 계약 고정"으로 확장
- 범위에 MLOps 계약 정의 항목을 추가
- 비범위에 MLOps 인프라 실제 구축(CI/CD, 레지스트리, 모니터링 도구)을 명시해 구현 범위 오해를 방지

### 2.2 목표 및 성공 기준 확장

- 제품 목표에 운영 계약 기반 품질 게이트 설계 훈련 목표를 추가
- 성공 기준에 아래 항목을 추가
  - 데이터 계약 검증 테스트 100% 통과
  - 서빙 계약(요청/응답 스키마, 오류 코드) 테스트 100% 통과
  - 운영 게이트 기준선 위반 시 배포 차단 규칙 검증

### 2.3 요구사항 구조 개편

- `Dual-Track 요구사항`을 `Tri-Track 요구사항 (Dual-Track + MLOps Track)`으로 개편
- 신규 섹션 `6.3 MLOps Track` 추가
  - Data Contract
  - Model Artifact Contract
  - Serving Contract
  - Monitoring Contract

## 3. 상세 보완 내용

### 3.1 Use Case 확장

- 기존 `UC-01`~`UC-05` 유지
- 신규 `UC-06`~`UC-08` 추가
  - `UC-06`: 데이터 계약 검증
  - `UC-07`: 서빙 계약 검증
  - `UC-08`: 운영 알림 판정

### 3.2 인수 기준(AC) 확장

- 기존 `AC-01`~`AC-04` 유지
- 신규 `AC-05 MLOps 계약` 추가
  - 데이터 스키마/규칙 위반 시 파이프라인 게이트 실패
  - 기준선 미달 모델 배포 승격 차단
  - 서빙 계약 일치성 유지
  - 운영 임계치 초과 시 알림 이벤트 생성

### 3.3 추적성 매트릭스 강화

- 기존 체인:
  - `Concept -> Rule -> Use Case -> Contract -> Test -> Component`
- 확장 체인:
  - `Concept -> Rule -> Use Case -> Contract -> Test -> Component -> Pipeline Stage`
- MLOps 관련 테스트 ID(`T-OPS-RED-*`) 및 파이프라인 단계 연결 행을 추가

### 3.4 릴리스 승인 기준 업데이트

- Dual-Track 기준을 Tri-Track 기준으로 확장
- 운영 게이트(데이터 검증/모델 승격/서빙 계약/알림 계약)가 테스트와 연결되어야 함을 승인 기준으로 추가

## 4. 현재 문서 상태 평가

- 강점
  - Invariant, 오류 계약, AC, Gate, Traceability 구조가 유지되어 테스트 전환이 쉽다.
  - UI/Logic 분리 원칙이 흔들리지 않은 상태에서 운영 계약을 추가했다.
- 개선 완료 포인트
  - MLOps 관점에서 빠져 있던 요구사항, 인수 기준, 추적성, 승인 기준을 문서 레벨에서 보완했다.

## 5. 기대 효과

- 기능 요구사항과 운영 요구사항을 분리된 계약으로 다루어 변경 영향 범위를 축소
- 개발 단계(TDD)와 운영 단계(MLOps)를 동일한 추적성 체계로 연결
- 배포 품질 게이트를 문서에서 선명하게 정의하여 회귀/운영 리스크를 조기 차단

## 6. 다음 권장 작업

- `T-OPS-RED-*` 테스트 명세를 테스트 파일 구조와 1:1로 매핑
- 파이프라인 단계별 게이트 조건(예: latency, 실패율, 품질 기준선) 수치 확정
- 오류 코드 고정 메시지 사전을 별도 문서 또는 상수 모듈로 분리해 재사용
